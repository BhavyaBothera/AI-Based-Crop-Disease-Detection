**Author**: Senior Python Engineer, ML Evaluation Engineer & Computer Vision Reliability Specialist  
**Audit Scope**: Correctness, Scientific Integrity, and Preprocessing Parity in `ml/evaluation/field_validation/`  
**Date**: November 20, 2026

---

## Executive Summary

A targeted P0 engineering audit and repair of the field validation pipeline (`ml/evaluation/field_validation/`) in the **PHYTOSIGNAL** repository was conducted. The primary objective was to ensure that real-world field evaluations and generalization audits produce scientifically trustworthy, reproducible metrics without silently defaulting labels, hardcoding baseline references, masking fallback heuristics as neural models, or introducing preprocessing divergence from production serving.

All 8 identified architectural and correctness defects were repaired, validated with 49 regression and unit tests, and verified across backend, ML pipeline, and frontend test suites with zero regressions. No model weights, dataset splits, class IDs, or production acceptance thresholds were modified.

## 1. Confirmed Bugs & Root Cause Analyses

### Bug 1: Gate Ground-Truth Labels Hardcoded / Defaulted
- **Confirmed Issue**: In `runner.py`, every manifest sample evaluated by `LeafGateEvaluator` was instantiated with `ground_truth_category="supported_leaf"`. Unsupported plant species (e.g., Apple, Corn, Weed) and non-leaf objects (e.g., background soil, gloves) were erroneously forced into the `supported_leaf` category. Furthermore, unknown or ambiguous labels silently became `supported_leaf`.
- **Root Cause**: Absence of an explicit gate ground-truth mapping function and failure to ingest `crop` or OOD category metadata into the gate evaluation pipeline.
- **Scientific Impact**: Underreported False Rejection Rate (FRR) and rendered False Acceptance Rate (FAR) uncomputable because negative classes were never labeled as negative.

### Bug 2: Preprocessing Disparity Between Production and Evaluation
- **Confirmed Issue**: `evaluator.py` claimed exact preprocessing parity with production serving (`backend/app/services/inference.py`), but maintained an independent reimplementation with divergent thresholds:
  - Evaluation had a hardcoded uniform canvas threshold of `3.0`, whereas production was configured at `2.0` (`UNIFORM_CANVAS_STD_THRESHOLD = 2.0`).
  - Format checks, minimum dimension validation, and Level A prevalidation logic were duplicated, risking drift across codebases.
- **Root Cause**: Two independently maintained preprocessing functions performing image decoding, EXIF orientation handling, canvas standard deviation checks, and bilinear resizing.
- **Scientific Impact**: Field validation images could pass or fail Level A validation in evaluation while behaving differently when uploaded to the FastAPI production `/api/predict` endpoint.

### Bug 3: Hardcoded Controlled Baseline Metrics in Comparative Analysis
- **Confirmed Issue**: In `runner.py`, `generate_baseline_comparison(controlled_report_path, field_results)` accepted `controlled_report_path`, but completely ignored the file argument and used hardcoded constants:
  ```python
  ctrl_acc = 0.968942
  ctrl_f1 = 0.965288
  # Line 245: 0.9971
  ```
- **Root Cause**: The function was stubbed with hardcoded metrics from an earlier test run instead of implementing a real parser for the JSON and Markdown report formats generated by the test evaluation pipeline.
- **Scientific Impact**: Inability to benchmark against new checkpoints or baseline runs; failure to reject missing, corrupt, or mismatched baseline reports; complete loss of baseline provenance.

### Bug 4: Verification Policy Default Inclusion of Suspected Samples
- **Confirmed Issue**: The field collection protocol states that visually suspected and ambiguous-unresolved samples must not be included in primary formal test metrics. However, in `evaluator.py` and `runner.py`, exclusion was optional and disabled by default (`exclude_unverified_from_primary: bool = False`, `--exclude-unverified` was `action="store_true"` default `False`).
- **Root Cause**: Default evaluation parameters processed all manifest records regardless of `verification_status`.
- **Scientific Impact**: Unverified and speculative field labels contaminated benchmark test metrics, degrading confidence in model accuracy and generalization assessments.

### Bug 5: Disease vs. Gate Data Separation and Label Space Ambiguity
- **Confirmed Issue**: The manifest allowed non-Solanaceae crops and gate-only labels (`non_leaf`, `other_plant`), but the disease evaluator expects 15 Solanaceae disease classes. Evaluator loops risked assigning unmapped disease labels a sentinel class ID `-1` or crashing during confusion matrix generation.
- **Root Cause**: Absence of an explicit record evaluation task attribute distinguishing disease evaluation (`15 classes`), gate evaluation (`3 classes`), or combined evaluation.
- **Scientific Impact**: Risk of invalid task-label combinations corrupting supervised confusion matrices and Macro-F1 calculations with out-of-vocabulary indices.

### Bug 6: Manifest and Dataset Integrity Vulnerabilities
- **Confirmed Issue**:
  - `load_and_validate_manifest` did not enforce uniqueness of `image_id`. Duplicate IDs could overwrite records or skew evaluation weights.
  - Manifest relative file paths were not checked for directory traversal (`..`).
  - `DataQualityAuditor` lacked duplicate-group consistency auditing across samples sharing the same `duplicate_group_id` (e.g., conflicting crop or diagnosis within the same plant session).
  - Cross-partition duplicate leakage only checked group IDs without verifying identical SHA-256 hashes across `field_dev` and `field_test`.
- **Root Cause**: Permissive validation checks focused solely on column presence rather than relational integrity and filesystem isolation.
- **Scientific Impact**: Potential dataset leakage between development and test partitions; vulnerabilities to filesystem escapes.

### Bug 7: Metric Reliability & Cluster Independence Deficiencies
- **Confirmed Issue**: In `metrics.py`:
  - Empty dataset inputs caused division by zero.
  - Single-class datasets or datasets missing classes produced misleading Macro-F1 scores (e.g. dividing single-class F1 of 1.0 by 15 classes with zero support, resulting in 0.0667).
  - Unobserved classes were not tracked or explicitly reported.
  - NaN and infinite raw scores could propagate through summary statistics.
  - Bootstrap confidence intervals performed standard i.i.d. observation resampling, which falsely narrows confidence intervals when multiple photographs originate from the same plant/session cluster (`duplicate_group_id`).
  - Image-level metrics were not distinguished from plant/cluster-level metrics.
- **Root Cause**: Standard classification metrics libraries assume i.i.d. test observations and fixed multi-class distributions.
- **Scientific Impact**: Overconfident confidence intervals failing to reflect true field sampling variance, and distorted Macro-F1 on partitioned evaluation subsets.

### Bug 8: Gate Fallback Transparency and Sidecar Validation
- **Confirmed Issue**: `LeafGateEvaluator` failed to explicitly declare whether evaluation results were produced by the trained neural gate model (`leaf_gate.keras`) or the deterministic rule-based plant screen fallback (`backend/app/services/input_gate.py`). Missing gate model files silently produced fallback metrics that could be cited as trained neural gate performance. Sidecar configs (`gate_model_config.json`) and model output dimensions were unvalidated.
- **Root Cause**: The evaluator relied on `leaf_gate_service` fallback mechanisms without surfacing model presence flags in the evaluation report metadata or summary markdown.
- **Scientific Impact**: Heuristic rule-based results could be cited as neural gate benchmark performance, compromising scientific truthfulness.

## 2. Exact Fixes Implemented

### Fix 1: Explicit Gate Ground-Truth Mapping (`manifest_schema.py`, `runner.py`, `gate_evaluator.py`)
- Defined canonical gate category constants:
  ```python
  GATE_CATEGORY_SUPPORTED_LEAF = "supported_leaf"
  GATE_CATEGORY_OTHER_PLANT = "other_plant"
  GATE_CATEGORY_NON_LEAF = "non_leaf"
  VALID_GATE_CATEGORIES = {GATE_CATEGORY_SUPPORTED_LEAF, GATE_CATEGORY_OTHER_PLANT, GATE_CATEGORY_NON_LEAF}
  ```
- Implemented `map_ground_truth_to_gate_category(ground_truth_class: str, crop: Optional[str] = None) -> str`:
  - Maps 15 Solanaceae classes and supported crops to `supported_leaf`.
  - Maps non-Solanaceae crops (Apple, Corn, Grape, Weeds, etc.) to `other_plant`.
  - Maps non-leaf objects (soil, glove, hand, background, irrigation pipe) to `non_leaf`.
  - Rejects unknown or ambiguous tokens (`""`, `"unknown"`, `"ambiguous"`, `"null"`) with `ValueError`.
  - Never silently defaults to `supported_leaf`.
- In `runner.py`, filtered gate samples to `evaluation_task in ("gate", "both")`, mapped each sample with `map_ground_truth_to_gate_category`, and logged/reported unmapped samples.
- In `gate_evaluator.py`, validated that `sample.ground_truth_category in VALID_GATE_CATEGORIES` before evaluation.

### Fix 2: Preprocessing Single Source of Truth (`backend/app/services/inference.py`, `ml/evaluation/field_validation/evaluator.py`)
- Updated `backend.app.services.inference.preprocess_image`:
  - Added `enforce_level_a: Optional[bool] = None` parameter (defaults to `ENABLE_LEVEL_A_PREVALIDATION`), preserving 100% of existing production API signatures and behavior.
- Refactored `ml.evaluation.field_validation.evaluator.preprocess_field_image`:
  - Eliminated duplicated decoding, EXIF orientation handling, resizing, and threshold checks.
  - Directly delegates to `backend.app.services.inference.preprocess_image`.
  - Imports authoritative shared constants (`TARGET_IMAGE_SIZE`, `ALLOWED_PIL_FORMATS`, `MIN_IMAGE_DIMENSION`, `MAX_IMAGE_PIXELS`, `UNIFORM_CANVAS_STD_THRESHOLD = 2.0`) from `backend.app.config`.
  - Preserved raw float32 RGB input range in `[0.0, 255.0]`.

### Fix 3: Real Controlled Baseline Parsing & Provenance (`ml/evaluation/field_validation/runner.py`)
- Implemented `parse_controlled_baseline(controlled_report_path: Union[Path, str]) -> Dict[str, Any]`:
  - Supports both JSON (`.json`) and Markdown (`.md`) reports generated by `ml/scripts/evaluate_test_split.py`.
  - In JSON: extracts `test_accuracy` (or `accuracy`), `test_macro_f1` (or `macro_f1`), `test_top_3_accuracy`, `timestamp_utc`, and `model_checkpoint`.
  - In Markdown: uses regex to extract Primary Macro-F1, Accuracy, Top-3 Accuracy, Evaluation Date, and Model Checkpoint.
  - Strictly validates that `accuracy` and `macro_f1` are present and in `[0.0, 1.0]`.
  - Raises `FileNotFoundError` if the report is missing, and `ValueError` if malformed or metrics are missing.
  - Never silently falls back to hardcoded numbers.
- In `generate_baseline_comparison`:
  - Calculates genuine deltas: `delta_acc = field_acc - baseline["accuracy"]`, `delta_f1 = field_f1 - baseline["macro_f1"]`.
  - Renders complete provenance: source file path, model checkpoint, and baseline timestamp.

### Fix 4: Authoritative Verification Policy (`manifest_schema.py`, `metrics.py`, `evaluator.py`, `runner.py`)
- Defined verification tiers:
  ```python
  VERIFIED_TIERS = {"expert_verified", "laboratory_confirmed"}
  UNVERIFIED_TIERS = {"visually_suspected", "ambiguous_unresolved"}
  ```
- In `calculate_field_metrics` and `evaluate_manifest`:
  - Set `exclude_unverified: bool = True` (and `exclude_unverified_from_primary: bool = True`) as the default.
  - Excluded visually suspected and ambiguous-unresolved records from primary metrics.
  - Computed both primary verified metrics and full exploratory metrics.
  - Tracked and reported `verified_sample_count`, `excluded_unverified_count`, and `unverified_breakdown` (counts by verification status).
- In `runner.py`:
  - Set `--exclude-unverified` to default `True`.
  - Added `--include-unverified` (setting `exclude_unverified=False`) for optional exploratory runs.

### Fix 5: Disease vs. Gate Task Separation (`manifest_schema.py`, `evaluator.py`)
- Introduced explicit evaluation task field: `ALLOWED_EVALUATION_TASKS = {"disease", "gate", "both"}`.
- Enforced task-label alignment in `FieldSampleRecord.validate()`:
  - If `evaluation_task in ("disease", "both")`: `crop` must be in `ALLOWED_CROPS`, `ground_truth_class` must be in `RAW_CLASS_TO_CROP`, and crop must match expected crop.
  - If `evaluation_task == "gate"`: allows any crop or non-leaf object, requiring only that `map_ground_truth_to_gate_category` cleanly resolves to a valid gate category.
- In `evaluator.py`:
  - Filtered records to `getattr(r, "evaluation_task", "both") in ("disease", "both")`, cleanly bypassing gate-only samples without assigning `gt_id = -1`.

### Fix 6: Manifest Security & Relational Data Auditor (`manifest_schema.py`, `data_auditor.py`)
- In `manifest_schema.py`:
  - Enforced unique `image_id` during parsing; duplicate IDs immediately raise `ManifestValidationError`.
  - Enforced safe relative path resolution; prohibited directory traversal (`..` in file path parts).
- In `data_auditor.py`:
  - Implemented dataset-root containment and symlink escape checks on all sample paths.
  - Implemented duplicate-group consistency audit: verifies that samples with the same `duplicate_group_id` have matching `crop`, `ground_truth_class`, and `disease_severity`. Flagged inconsistencies in `report.duplicate_group_inconsistencies` and marked `is_clean = False`.
  - Added SHA-256 cross-split duplicate tracking to `group_leaks`.

### Fix 7: Reliable Metrics & Cluster-Aware Bootstrapping (`metrics.py`)
- Empty dataset protection: returns zeroed metrics (`accuracy = 0.0`, `macro_f1 = 0.0`, `accuracy_ci_95 = (0.0, 0.0)`) without ZeroDivisionError.
- Single-class and missing-class handling:
  - Dynamically calculates Macro-F1 across `observed_labels = [idx for idx in CLASS_NAMES if support > 0 or pred > 0]`. When 1 class is present, Macro-F1 accurately reflects that class rather than artificially deflating to 0.0667.
  - Explicitly records `observed_classes_count` and lists `unobserved_classes`.
- NaN and Infinite score protection: sanitizes prediction scores in confidence distributions.
- Cluster-aware bootstrap:
  - In `bootstrap_macro_f1_ci`, resamples at the cluster level (`duplicate_group_id` / plant group) rather than i.i.d. observation level.
  - Does not report misleading bootstrap intervals when independent clusters (<3) or samples (<5) are insufficient.
- Distinguishes image-level from plant-level metrics: calculates `cluster_metrics` (`cluster_accuracy`, `cluster_count`, `cluster_correct`) using cluster majority voting.

### Fix 8: Gate Fallback Transparency & Sidecar Validation (`gate_evaluator.py`)
- Evaluator introspection:
  - Sets `self.is_trained_model = bool(getattr(self.service, "is_loaded", False))`.
  - Sets `self.gate_backend = "trained_model" if self.is_trained_model else "deterministic_fallback"`.
- Validates sidecar configuration (`gate_model_config.json`) and model output dimensions against expected 3 classes.
- In `evaluate_dataset`:
  - Records `is_trained_model`, `gate_backend`, `deterministic_fallback_active`, and `sidecar_validation` in `metadata`.
  - If fallback is active, adds `warning: "EVALUATION_PERFORMED_ON_DETERMINISTIC_FALLBACK_NOT_TRAINED_GATE_MODEL"`.
- In `generate_markdown_summary`:
  - Renders `Gate Backend` and `Trained Model Evaluated: YES / NO`.
  - When evaluating on fallback, prints a prominent `> [!WARNING]` callout:
    ```markdown
    > [!WARNING]
    > **DETERMINISTIC FALLBACK EVALUATION NOTICE**
    > This evaluation was executed using the deterministic rule-based plant screening fallback,
    > NOT the trained `leaf_gate.keras` neural model. These metrics reflect heuristic baseline
    > capabilities only and must NOT be cited as trained neural gate performance.
    ```

## 6. Remaining Limitations

1. **Perceptual Hash Collisions on Extreme Downsampling**: While dHash duplicate detection catches near-identical captures, low-contrast natural foliage images with high-frequency sensor noise can occasionally exhibit dHash distances near the boundary threshold (default distance <= 6). Manual pathologist spot-checks remain recommended for borderline near-duplicates.
2. **Cluster Bootstrap Group Size Sensitivity**: When an evaluation partition contains fewer than 3 independent duplicate groups (`duplicate_group_id`), the cluster-aware bootstrap confidence interval collapses to point estimates to prevent misleadingly narrow or unstable intervals. Field data collection should ensure at least 15–20 distinct plant clusters per class.
3. **Level A Prevalidation Boundary Cases**: EXIF metadata stripping in mobile browser uploads may cause images taken in portrait orientation to enter the pipeline in raw sensor orientation unless browser-side canvas rotation is active. Both production and field validation handle EXIF orientation tags identically via PIL `ImageOps.exif_transpose`, but images already stripped of EXIF tags cannot be automatically re-oriented.
